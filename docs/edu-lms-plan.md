# EDU → повноцінна LMS: план перетворення

> Живий документ. Узгоджено в сесії grill-me (2026-06-15). Оновлювати при зміні рішень.

## Контекст і обмеження

- **Ціль:** перетворити EDU-версію StudyCod на повноцінну LMS рівня міжнародного **SaaS-продукту**, що покриває 4 виміри якості: функціональний паритет з LMS, формальні стандарти/інтеграції, промислова надійність, педагогічна повнота.
- **Реальність:** соло-розробник + Claude, без жорсткого дедлайну, без названого першого клієнта.
- **Жорстке обмеження:** ця перебудова — root-level зміна EDU. Вона **НЕ сміє зламати StudyCod Personal і Contest**, які ділять спільні `User`/auth/частину сервісів.
- **Принцип порядку:** інкрементальний SaaS-фундамент. Жодного багатомісячного «невидимого» ретрофіту наперед і жодного відкладання архітектури «на потім». Кожна фаза лишає продукт робочим і демонстрабельним.

## Зафіксовані архітектурні рішення

### Тенантність і ідентичність
1. **Мультитенантність:** shared-DB + `org_id`, нова сутність `Organization`, роль OrgAdmin.
2. **Ідентичність:** єдиний `User` + нова `Membership(user, org, role)`. `Student` стає профілем учня в класі, прив'язаним до `User`.
   - **`User`-и недоторкані** (це реальні акаунти).
   - Старі `Student`-shell-акаунти — одноразові: можна видаляти/перестворювати при міграції.
3. **Ролі (5 фіксованих, матриця прав у коді):** OrgAdmin, Teacher, Assistant/TA (редагує, не видаляє), Student, Parent/Observer (читає прогрес своєї дитини).
4. **Провіженінг/вхід:** self-signup (створює Org → стає OrgAdmin) + invite вчителів по email/посиланню + join-коди класу для учнів. Google OAuth уже є. SSO/SAML/SCIM/LTI — відкладено у Фазу 3.
5. **Ізоляція (критично для захисту Personal/Contest):** `Organization`/`Membership`/`org_id` живуть **тільки в EDU-підсистемі та нових таблицях**. `User.role` і Personal/Contest-таблиці (`Task`, `Grade`, `Topic`, …) недоторкані. Окремий org-context middleware вішається **лише на `/edu`**. Personal-юзер просто не має Membership.

### Продукт і контент
6. **Модель контенту:** лишається **code-first** (CODE/WEB-задачі — ядро й диференціація). Додаються лише table-stakes:
   - універсальне завдання з **ручною перевіркою** (файл/текст);
   - нормальний **quiz-движок** (з сирого `quiz_json` у справжню модель);
   - **контент-сторінки** (відео/документ як першокласний об'єкт).
   - **Без** форумів, SCORM-авторингу, H5P, wiki.
7. **Багаторазовість:** **Course-template → assign у Class**. Course/Module — багаторазові (рівень org або глобальний каталог), Class — екземпляр курсу з ростером/дедлайнами/оцінками.
   - **Семантика:** **fork-on-assign** (знімок-копія при призначенні) + **opt-in pull** оновлень.
   - **Pull-UX:** банер «шаблон оновлено: N змін» + **per-item вибір** (додано/змінено/видалено). Локально змінені вчителем елементи позначаються й не перезаписуються без підтвердження.
8. **Грейдбук:** узагальнити. Ядро — `raw-100` (вже так). Зверху — **плагінні схеми відображення** (12-бальна UA / letter A–F / GPA / %) + **зважені категорії** (homework 20% / exams 50% …), drop-lowest, rubric. Українська 12-бальна (LINEAR/MON, тематичні формули, семестри) стає **одним плагіном**, нічого не викидається.
9. **i18n (Фаза 2):** i18n-фреймворк, **базова локаль = en**, uk першокласна. Extract-as-you-go (новий EDU-UI одразу через ключі, старі рядки мігрують поступово). Контент — машинний переклад (`titleEn`-патерн) + override автора.
10. **Захист даних неповнолітніх (COPPA/FERPA/GDPR-K) — design-for-later:** у Фазі 1 закласти лише дешеві хуки:
    - інтерфейс **export/erasure** (right-to-erasure);
    - поля **вік/дата народження + прапорець батьківської згоди** на профілі учня;
    - **журнал доступу до даних учня** (лягає на audit-лог Фази 0).
    - Повна машинерія (consent-flow, residency, DPA) — Фаза 3 під реального клієнта.

### Розв'язані під-вузли
11. **Parent↔Student лінк:** **інвайт від вчителя/OrgAdmin** для конкретної дитини (email/посилання/код). Школа контролює, хто кому батько — найбезпечніше для даних дітей.
12. **Quiz-движок обсяг:** авто-типи (single/multiple choice, true/false, short-answer з точним/regex матчем, fill-in-blank, matching) **+ один open-text** з ручною перевіркою (перевикористовує manual-grade).
13. **Тестовий бар Фази 0:** **risk-based**, без погоні за відсотком. Обов'язкові unit на: грейдинг/конверсію/формули (тихі баги), judge/антиплагіат, авторизацію/RBAC. Плюс інтеграційні smoke-тести, що Personal/Contest-флоу не зачеплені.

## Фазовий план

### Фаза 0 — Стабілізація (невидима, де-ризикує все)
- **Redis** замість критичних in-memory станів Live Classroom (`liveCode`, `liveChallenge`, `liveBreakout`, `liveCopilot` — зараз не переживуть multi-replica).
- **Risk-based тести** (див. п.13) + регрес-захист Personal/Contest.
- Безпека, RBAC-аудит, **audit-логування** (фундамент під data-access журнал п.10).
- Усунення техборгу, що вже впливає на надійність.

### Фаза 1 — Мінімальний SaaS-каркас
- `Organization`, `Membership`, org-scoped RBAC **тільки на `/edu`**, єдиний `User` як канон.
- Self-signup + invite + join-коди (п.4).
- Parent↔Student лінк (п.11).
- Дешеві комплаєнс-хуки (п.10).
- **Без** SAML/SCIM/custom roles/marketplace.
- *Мета: фундамент, який потім не доведеться ламати.*

### Фаза 2 — Видима цінність
- Course Templates + versioning (fork-on-assign + opt-in pull, п.7).
- Manual assignments + file upload (п.6).
- Quiz-движок (п.12).
- Контент-сторінки (відео/док).
- Узагальнений грейдбук: зважені категорії + плагінні схеми (п.8).
- i18n-фреймворк, en як база (п.9).
- Покращення AI/Live-функцій.
- *Мета: користувачі бачать нові можливості, а не лише внутрішні рефактори.*

### Фаза 3 — Масштабування
Тригери старту: 2+ незалежні організації / платні клієнти / реальний enterprise-запит.
- SSO/SAML, SCIM, LTI.
- Advanced RBAC.
- Marketplace курсів, міжорганізаційний обмін контентом.
- Повний комплаєнс (consent-flow, residency, DPA).

## Ключові ризики
- **Регрес Personal/Contest** — мітигація: ізоляція org-логіки в `/edu` + smoke-тести (Фаза 0/1).
- **Соло без дедлайну** — мітигація: кожна фаза робоча й демонстрабельна; не починати Фазу N+1 до робочого стану Фази N.
- **Ставка на непідтверджений попит** — мітигація: Фаза 3 (дорогий enterprise) гейтнута реальними тригерами.
