# StudyCod design audit and implementation register

**Scope:** public pages, learner workspace, EDU, contests, IDE, administration, and shared shells.
**Review inputs:** production site at `https://studycod.space`, local source in this workspace, and the reference boards in `design/references/`.
**Status:** the interaction/accessibility pass was deployed in release `f4a2e6e`. The expanded shared-shell visual pass is implemented locally and is pending its next deployment. Role-protected paths were checked in code where a live signed-in scenario was unavailable.

The baseline observations are recorded separately from current implementation status. Acceptance checks marked **preview required** still need a signed-in role and manual visual verification; a code change alone does not prove the production scenario is closed.

## Verification matrix

| Scenario | Current evidence | Completion criterion |
|---|---|---|
| Widths 320, 390, 768, 1024, 1366, 1920 | Responsive IDE tabs and shell controls are implemented; build/test checks do not replace visual review. | No horizontal page overflow; IDE actions and active pane remain visible. |
| Both themes and languages | Semantic design tokens, localization pairs and accessible labels exist in the touched paths. | Capture matched screenshots in `uk/en` and light/dark. |
| 200% zoom and keyboard | Skip targets, tab keyboard behavior and focus rings are implemented. | Confirm focus order, menu reachability, Escape, focus return and no clipped controls. |
| Contrast | Shared semantic theme tokens are documented; a full contrast scan has not been run across legacy surfaces. | Verify ordinary text at least 4.5:1 and large text at least 3:1 in both themes, per [WCAG 2.2 AA](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html). |
| Reduced motion | Shared CSS, Modal, landing reveal and completion feedback provide reduced-motion variants. | Confirm no movement, scale, blur or decorative loop in affected screens. |
| Learning provider errors | Classifier tests cover six states; provider catch leaves previously loaded course data intact. | Use controlled API responses to verify each UI state and retry. |
| IDE persistence | Pane reconciliation/save label helpers have unit tests; Monaco remains mounted. | Manual test confirms cursor, scroll, source, language and stdin across tabs. |
| Production | Release `f4a2e6e` with the interaction/accessibility pass is live; the user reported the protected UI still looked too similar. The expanded shared-shell pass is local and not yet published. | Re-run the visual matrix after the next release, including authenticated EDU/contest/admin roles. |

## Current evidence boundary

The test suite verifies state classification and the editor feedback rules. Type checking and production build verify the local bundle and lazy-load boundary. They do not verify authenticated production data, keyboard behavior on a real mobile device, contrast ratios for every legacy surface, or every role-specific route. The expanded shell pass is authorized for deployment; role-specific production review remains part of the post-deploy check.
